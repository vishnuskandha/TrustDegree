# Internationalization (i18n) Guide

TrustDegree supports multiple languages using **react-i18next**. This guide explains how the system works and how to add new languages.

---

## Current Languages

| Language | Code | Status | Translation Coverage |
|----------|------|--------|---------------------|
| English | `en` |  Complete | 100% |
| Tamil | `ta` |  Partial | 100% keys, values need human translation |

---

## Architecture

### Setup

```typescript
// src/i18n.ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';

i18n
  .use(initReactI18next)
  .init({
    lng: localStorage.getItem('language') || 'en',
    fallbackLng: 'en',
    interpolation: {
      escapeValue: false, // React handles XSS
    },
    resources: {
      en: {
        common: require('./locales/en/common.json'),
        pages: require('./locales/en/pages.json'),
        errors: require('./locales/en/errors.json'),
        web3: require('./locales/en/web3.json'),
      },
      ta: {
        common: require('./locales/ta/common.json'),
        pages: require('./locales/ta/pages.json'),
        errors: require('./locales/ta/errors.json'),
        web3: require('./locales/ta/web3.json'),
      },
    },
  });

export default i18n;
```

Imported in `src/main.tsx`: `import './i18n';`

---

### Translation File Structure

Translations are organized into namespaces:

```
locales/
├── en/
│   ├── common.json     # Reusable strings (nav, actions, status)
│   ├── pages.json      # Page-specific content
│   ├── errors.json     # Validation & API errors
│   └── web3.json       # Web3 term explanations
└── ta/
    ├── common.json
    ├── pages.json
    ├── errors.json
    └── web3.json
```

### Namespace Purposes

- **`common`**: Shared UI strings (buttons, labels, navigation, status messages)
- **`pages`**: Content for each page (Home, Issue, Verify, Credentials, HowItWorks, TechnicalDocs)
- **`errors`**: Form validation errors, API error messages, toast notifications
- **`web3`**: Tooltips and explanations for blockchain terminology (hover helps)

## Using Translations in Components

### Basic Usage

```tsx
import { useTranslation } from 'react-i18next';

function MyComponent() {
  const { t } = useTranslation();

  return <h1>{t('pages.home.hero.title')}</h1>;
}
```

### Nested Keys

Translation files support nested objects:

```json
{
  "pages": {
    "home": {
      "hero": {
        "title": "Trusted Digital Diplomas",
        "subtitle": "Your certificates on blockchain"
      }
    }
  }
}
```

Access with dot notation: `t('pages.home.hero.title')`

---

### Variables (Interpolation)

```tsx
// Translation
{
  "greeting": "Hello, {{name}}!",
  "stats": "{{count}} degrees issued"
}

// Usage
t('greeting', { name: user.name });
t('stats', { count: 15000 });
```

---

### Pluralization

```json
{
  "items": "{{count}} item",
  "items_plural": "{{count}} items"
}
```

```tsx
t('items', { count: 1 }); // "1 item"
t('items', { count: 5 }); // "5 items"
```

---

### Context (Gender, Formality)

```json
{
  "status": {
    "male": "He is verified",
    "female": "She is verified",
    "neutral": "They are verified"
  }
}
```

```tsx
t('status.' + user.gender, { context: user.gender });
```

*(Not currently used, but available if needed for Tamil honorifics)*

## Extracting Strings

When adding new user-facing text to components:

1. **Add key to translation files:**
   - `src/locales/en/common.json` (or pages.json, errors.json, web3.json)
   - `src/locales/ta/common.json` (same structure, Tamil value or placeholder)

2. **Replace hardcoded string with `t()`:**
   ```tsx
   // Before
   <h1>Verify Credential</h1>

   // After
   <h1>{t('pages.verify.title')}</h1>
   ```

3. **Run the app** - if key missing, console shows warning with missing key.

## Language Switcher Component

The LanguageSwitcher is already implemented in `src/components/layout/LanguageSwitcher.tsx`:

```tsx
import { useTranslation } from 'react-i18next';

export function LanguageSwitcher() {
  const { t, i18n } = useTranslation();

  const languages = [
    { code: 'en', label: 'English' },
    { code: 'ta', label: 'தமிழ்' },
  ];

  return (
    <div className="flex gap-2">
      {languages.map((lang) => (
        <Button
          key={lang.code}
          variant={i18n.language === lang.code ? 'default' : 'outline'}
          size="sm"
          onClick={() => i18n.changeLanguage(lang.code)}
        >
          {lang.label}
        </Button>
      ))}
    </div>
  );
}
```

## Adding a New Language

### 1. Create Translation Directory

```bash
cp -r src/locales/en src/locales/es  # Example: Spanish
```

### 2. Translate Values

Edit `src/locales/es/common.json`, `pages.json`, `errors.json`, `web3.json`.

**Keep keys identical** - only translate the values.

```json
{
  "nav": {
    "home": "Inicio",
    "verify": "Verificar"
  }
}
```

**Do NOT change key names** like `pages.home.hero.title`. Keys are language-agnostic identifiers.

---

### 3. Update LanguageSwitcher

Add button in `src/components/layout/LanguageSwitcher.tsx`:

```tsx
const languages = [
  { code: 'en', label: 'English' },
  { code: 'ta', label: 'தமிழ்' },
  { code: 'es', label: 'Español' }, // NEW
];
```

---

### 4. Test

```bash
npm run dev
# Click language switcher
# All text should update to new language
```

## Tamil Translation Notes

### Current Status

-  All translation keys created (same structure as English)
- Values are placeholder `"பதிப்பு வேண்டும்"` (needs translation)
- Need human translator or Tamil-speaking team member to translate values

### Translation Guidelines for Tamil

1. **Keep it simple:** Use everyday Tamil, not formal/written style
2. **Consistent terminology:** Once you translate "credential" as something, use same term throughout
3. **Respect technical terms:** Some Web3 words may not have common Tamil equivalents - use transliterations if needed (e.g., "ஸ்மார்ட் கான்ட்ராக்ட்", "பிளாக்செயின்")
4. **Cultural adaptation:** Analogies should resonate with Tamil audience (e.g., "Like a digital safe" → "ஒரு டிஜிட்டல் சேமிப்பு ப%C2%BF ... ")
5. **Readability:** Keep sentences short (max 20 words)

### Translation Priority

1. **Home page** (`pages.home.*`) - most visible
2. **Verify page** (`pages.verify.*`) - highest user traffic
3. **Common nav/actions** (`common.*`) - used everywhere
4. **Error messages** (`errors.*`) - user-facing errors
5. **Web3 explanations** (`web3.*`) - tooltips
6. **Issue page** (`pages.issue.*`) - admin only, lower priority
7. **Credentials page** (`pages.credentials.*`)
8. **HowItWorks page** (`pages.how.*`)
9. **TechnicalDocs** (`pages.technical.*`)

## Best Practices

###  DO:

-  Use meaningful translation keys (semantic, not the English text itself)
  ```json
  // Good
  { "nav.home": "Home" }
  // Bad
  { "home": "Home" }
  ```
-  Keep all strings in translation files (never hardcode)
-  Use nested structure for organization
-  Document unusual terms in `web3.json` for tooltips
-  Test with screen readers after adding translations (some languages have longer text)
-  Provide both English + Tamil buttons (even if Tamil incomplete, users can toggle)

###  DON'T:

-  Don't concatenate strings to form sentences (translations need word order flexibility)
  ```tsx
  // Bad
  t('welcome') + ', ' + user.name
  // Good
  t('welcomeUser', { name: user.name })
  ```
-  Don't use English in JSX and only translate parts - entire UI should be translatable
-  Don't change key structure mid-project (maintain backward compatibility)
-  Don't rely on Google Translate for Tamil (use human translators or leave as placeholder)

## Testing i18n

### Automated Tests

Add to your test suite:

```tsx
// src/__tests__/i18n.test.ts
import i18n from '@/i18n';

describe('i18n', () => {
  it('all keys in EN have corresponding TA keys', () => {
    const enKeys = Object.keys(require('../locales/en/common.json'));
    const taKeys = Object.keys(require('../locales/ta/common.json'));
    expect(taKeys).toEqual(enKeys);
  });

  it('no missing translations in used keys', () => {
    const usedKeys = extractUsedKeysFromComponents(); // custom script
    const enKeys = getAllKeys(require('../locales/en'));
    usedKeys.forEach((key) => {
      expect(enKeys).toContain(key);
    });
  });
});
```

---

### Manual Testing

1. **Switch languages** - Click Tamil button, verify all text updates
2. **Check RTL** - Not needed (Tamil is LTR)
3. **Long text overflow** - Tamil may be longer than English, test for:
   - Button truncation (add `truncate` class if needed)
   - Navigation wrapping (test narrow viewports)
   - Modal width (increase `max-w-*` if needed)
4. **Date/number formatting** - Currently using `toLocaleString()` - should adapt to locale automatically

### Date & Number Formatting

Use Intl API for locale-aware formatting:

```tsx
new Intl.NumberFormat(i18n.language).format(1000000);
// en: "1,000,000"
// ta: "10,00,000" (Indian numbering system)

new Intl.DateTimeFormat(i18n.language, {
  year: 'numeric',
  month: 'long',
  day: 'numeric',
}).format(date);
```

## Troubleshooting

### Issue: Language doesn't switch

**Check:**
1. `i18n.changeLanguage('ta')` called successfully?
2. Tamil JSON file exists and is valid JSON
3. Console has `Missing translation for key: ...` errors (means key doesn't exist in TA)
4. Clear localStorage: `localStorage.removeItem('i18nextLng')`

---

### Issue: Some text not translating

**Cause:** Hardcoded strings that need to be replaced with `t()`

**Fix:** Find the hardcoded string, add it to translation files, replace with `t('key')`

---

### Issue: Translations break on page reload

**Cause:** i18n initialization async, component renders before translations loaded

**Fix:** Already handled by `initReactI18next` - but if you see issues, ensure `i18n.ts` is imported BEFORE any component using `t()`:

```tsx
// main.tsx
import './i18n'; // MUST be imported before App
import App from './App';
```
